1 Project Ka Introduction & Background (Yeh Kya Hai Aur Kyu Banaya Gaya?)

1.1 Market Me Problem Kya Thi?

Aaj har business (jaise Gym, Restaurant, Jeweller, Doctor, Fashion Brand) chahta hai ki unke Instagram ke naye posts aur reels unki official website par automatic live dikhein.

Lekin jab koi business iske liye market me tool dhoondhta hai (jaise Elfsight, Tagembed, ya Smash Balloon), toh wo companies har website ke liye ₹1,000 se lekar ₹3,500 ($15–$50) har mahine charge karti hain! Agar kisi agency ke paas 10 clients hain, toh unhe har saal lakhon rupaye sirf ek widget ke dene padte hain.

1.2 Hamara Solution Kya Hai?

Humne ek aisa **in-house system** taiyar kiya hai jo directly official **Meta (Instagram / Facebook) Graph API** se connect karta hai. Yeh system photos aur reels ko apne server par download karke save kar leta hai aur kisi bhi website par bina kisi monthly charge ke **lifetime free** feed dikhata hai.

✨ Core Value Proposition: Market ke tools jaisa saara kaam karta hai, lekin ₹0 Monthly Cost me. Aap clients se iska one-time ya yearly charges lekar 100% profit kama sakte hain.
2 Meta Graph API Ki Poori Theory

2.1 API Kya Hoti Hai?

API ka full form hai Application Programming Interface. Yeh ek aisi khidki (bridge) hoti hai jiske zariye do alag softwares aapas me baat karte hain. Hamare case me hamara server Instagram ke server se puchta hai: "Batao is account par kaun se naye posts aaye hain?" aur Instagram JSON data me reply deta hai.

2.2 Instagram Personal vs Professional/Business Account:

Feature Personal Account Professional / Business Account
Cost Free Free (Instagram app me 1 minute me switch hota hai)
Graph API Access Nahi milta Full API Access milta hai
Facebook Page Linking Zaroori nahi Zaroori hai (Token generate karne ke liye)

2.3 Access Token Kya Hota Hai?

Access Token ek Digital Key (Password) ki tarah hota hai jo Meta Graph API ko batata hai ki aapko us specific Instagram account ka data padhne ki permission hai.

  • Short-Lived Token: Yeh sirf 1 se 2 ghante chalta hai (Test purpose ke liye).
  • Long-Lived Token (60 Days): Graph API Explorer me extend karne par yeh 60 Din ke liye valid ho jata hai.
  • Auto-Refresh Mechanism: Meta ek official refresh endpoint deta hai (https://graph.instagram.com/refresh_access_token). Hamara system har 30–45 din me is token ko background me automatically renew kar deta hai, isliye yeh Lifetime Unlimited chalta rehta hai.
⚠️ Token Kab Invalidate Hota Hai? Token sirf tabhi band hota hai jab user apna Instagram ya Facebook password change kar de, ya Instagram settings me jaakar App ko manually disconnect kar de. Normal chalte hue yeh kabhi band nahi hota.
3 Media Storage Engine (CDN Expiry Problem Aur Hamara Solution)

3.1 Instagram CDN Links 3 Din Me Expire Kyu Hote Hain?

Instagram ke photos aur videos ka link aamtaur par aisa hota hai: https://instagram.fpnq22-1.fna.fbcdn.net/.... Meta ki strict security policy hoti hai ki yeh links 3 din (72 ghante) baad expire ho jate hain.

Agar hum direct Instagram ke links website par lagayenge, toh 3 din baad client ki website par saari images gayab ho jayengi aur broken image icon aane lagega!

3.2 Hamara Permanent Local Storage Solution:

Is problem ko solve karne ke liye hamare backend me download_media() engine banaya gaya hai:

  1. Jab bhi Instagram se naya post detect hota hai, backend us photo (.jpg) ya reel video (.mp4) ko turant apne server ki disk (backend/media/) par download karke save kar leta hai.
  2. Database me Instagram ke expiring link ki jagah local path (jaise /media/18102065894198422.jpg) save kar diya jata hai.
  3. Client ki website hamare local server se image load karti hai. Yeh photos lifetime valid rehti hain aur kabhi broken nahi hoti!
4 Real-Time Auto Sync Engine (Bina Page Refresh Ke Live Update)

4.1 Background Worker Kya Karta Hai?

FastAPI server ke andar ek asynchronous task (periodic_instagram_sync) chalta hai jo har 15 second me Meta Graph API se latest media IDs mangwata hai.

4.2 Automatic Add & Delete Logic:

  • Naya Post Upload Hua: Backend naye post ko detect karta hai, media download karta hai, aur SQLite me insert kar deta hai.
  • Purana Post Delete Hua: Backend Instagram se aayi IDs ki list ko local database se compare karta hai. Jo ID Instagram par nahi milti, uske liye SQL query chalti hai: DELETE FROM instagram_posts WHERE ig_media_id NOT IN (...) aur wo post local database se turant delete ho jata hai.

4.3 Server-Sent Events (SSE) Ka Role:

Post add ya delete hone par server connected website ke browser ko ek SSE Signal (sync_completed) bhejta hai. Browser me chalta hua widget bina page reload kiye screen par post ko smoothly update kar deta hai (Zero Flickering).

5 Database Architecture (SQLite WAL Mode Ki Theory)

5.1 SQLite Kyu Chuna?

Aamtaur par log MySQL ya PostgreSQL use karte hain jisme alag se server install karna padta hai, username/password set karna padta hai aur backup lena mushkil hota hai.

Humne **SQLite** chuna kyunki yeh ek Single-File Database (insta_hub.db) hai:

  • Zero configuration: Na koi port chahiye, na user password.
  • Super Portable: Bas yeh ek file copy kar lijiye, poora database sath chala jata hai.
  • Ultra Fast: File direct disk par hoti hai, isliye query response time 5 millisecond se bhi kam hota hai.

5.2 WAL Mode (Write-Ahead Logging) Kya Hai?

Normal SQLite me jab koi data likh raha hota hai, toh doosra banda data padh nahi sakta (Database Lock error aa jata hai). Humne database me WAL Mode enable kiya hai: PRAGMA journal_mode=WAL; Isse ek taraf background sync naye posts likhta rehta hai aur doosri taraf hazaron visitors bina kisi rukawat ke website par feed padhte rehte hain!

6 Frontend Widget Embedding Ki Theory

6.1 iFrame vs Script Tag Embed:

Puraane jamane ke widgets iFrame me chalte the jo mobile par slow hote hain aur unka design parent website ke sath blend nahi hota. Hamara widget Pure Vanilla JS & CSS me bana hai:

  • Zero External Dependencies: Na React chahiye, na jQuery. Size sirf 8 KB hai, isliye website 1 second me load hoti hai.
  • Scoped CSS Classes: Sabhi styles .ig-card, .ig-card-media se scoped hain, taaki client ki website ke WordPress ya Bootstrap styles se kabhi conflict na ho.
  • Responsive Grid: Desktop par 3 columns, tablet par 2 columns aur mobile par 1 column automatic adapt hota hai.

6.2 Authentic Card Design:

Post card ka design authentic Instagram post jaisa banaya gaya hai: Gol Avatar, Username, 'View profile' button, Square photo/reel, 'View more on Instagram' link, Heart/Comment/Share action icons, Real likes count, aur caption toggle.

7 Client Onboarding SOP (Real World Business Process)

Jab bhi kisi client ka order aaye, yeh 4 steps follow karne hain:

STEP 1: Client se Instagram Business Account Confirm Karein Client ka Instagram account Professional/Business hona chahiye aur Facebook Page se link hona chahiye.
STEP 2: Client Ka Token Aur ID Nikalna Meta Developer Portal (developers.facebook.com/tools/explorer) par client ka Facebook Page select karke Token aur INSTAGRAM_ACCOUNT_ID generate karein.
STEP 3: Server Ke .env Me Update Karna Aapke server me backend/.env file me client ke details paste karke server run kar dein.
STEP 4: Client Ki Website Par Code Paste Karna Client ki website me container aur script laga dein: 
<div id="insta-feed-widget"></div>
<link rel="stylesheet" href="https://your-server.com/widget/insta-feed.css">
<script src="https://your-server.com/widget/insta-feed.js"></script>
<script>
  document.addEventListener('DOMContentLoaded', () => {
    InstaHub.init({
      container: '#insta-feed-widget',
      apiUrl: 'https://your-server.com'
    });
  });
</script>
